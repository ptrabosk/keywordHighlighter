# Architecture

The Offsight Highlighter is a Manifest V3 extension scoped to the supported Operations web application. Its content script loads the validated schema-v2 `opt_out_rules.json` registry (exactly 214 rules), highlights matching inbound message blocks, and observes the single-page application for changes. The rule runtime in `src/highlight/core.js` executes raw, normalized, exact, bounded, regex, guarded, and deterministic-detector rules from that registry; no legacy or normalized-ID rule asset is loaded. Popup and options pages load the same core and expose only the custom-keyword editor. The extension does not request or inspect the user's Chrome profile identity.

Each inbound message block is classified once. The content script collects the best match from every configured paragraph in the block, plus a Hot Topic survey classification when the reply is only a survey choice and one of the three preceding brand messages is the Hot Topic prompt. It then colors the block with the highest-priority rule. Priority is: whole-message tapback reactions, then emoji stop, then emoji-only replies, then Hot Topic replies, then category priority (opt out, fuzzy opt out, too many texts, texting explanation, reply, close; no-action rules never highlight). After the emoji checks, raw-message rules read the message with emojis removed, as the normalized rules already do. Brand prompts are never highlighted. Blocks are cached by their text, so unchanged messages are skipped without layout reads.

Shortcut telemetry is owned by `src/highlight/shortcutTelemetry.js` and the content script. The helper recognizes only five trusted Shift combinations (`Shift+D/N/B/C/E`) and counts rendered highlighted messages and escalation notes. The content script sends a sanitized, non-account-attributed event only when that count is positive. It does not prevent or alter the host page's keyboard handling.

The background service worker owns the local event queue, retry policy, and HTTPS uploads. The logging sanitizer is the client-side data boundary: only the approved operational event allowlist is queued, session lifecycle events are retained, shortcut events contain only the shortcut and a bounded highlight count, and other diagnostics use a bounded metadata allowlist. A highlight event is sent once per highlighted message per page session. The full supported-page URL (`https://ui.attentivemobile.com/concierge/*` only) is attached to content-script highlight, shortcut, and error events; all other URLs and account identifiers are rejected from the event contract. Google Apps Script is the server-side boundary. It authenticates with a rotatable shared ingestion token, validates the same event contract, applies daily quotas under a script lock, writes accepted rows (including the supported-page URL, but no account data) to Google Sheets, and deletes all event rows plus their deduplication IDs after 90 days.

Production and development permissions are separated at packaging time. `highlighter/manifest.json` is the Store-safe source manifest. `scripts/package-extension.ps1` produces a deterministic Store ZIP with release configuration injected from environment variables and the options page, or a localhost-capable development ZIP with the previous local public key.
